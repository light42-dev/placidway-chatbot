## (a) What changed, file by file

| File | Change |
|---|---|
| `bot/spelling.py` (new) | `correct(term, vocabulary)`: a query word (5+ letters) that appears in no passage is replaced by the closest indexed word (`difflib`, similarity at least 0.85). "PROSTRATE" now finds "prostate". It never changes words that are in the index, so retrieval for correctly spelled questions stays the same. I compared the top 3 passages for 13 general questions before and after: they were identical. |
| `bot/retriever.py` | (1) It calls `correct()` for unknown query words (one line in `Index.search`). (2) It has two new synonym groups: insurance/medicare/medicaid/tricare/insurer/coverage, and mobility/mobile/walker/wheelchair/cane/crutch/disabled/disability. "MEDICARE" and "WALKER" appear on no page, so without these groups the passages about insurance and mobility scored nothing. |
| `bot/guards.py` (new) | Checks in code after the model answers. (1) `add_missing_pointers`: if the reply says it doesn't know or that something is not listed but has no quote/contact pointer, it appends "You can request a free quote from PlacidWay for details." If the user's newest message asks about safety or their own health (safe, risk, diabetes, heart, AFib, medication, ...) and the reply names no doctor, it appends "Please talk to your doctor about what is right for you." (2) `quoted_passage`: finds the passage the reply copies at least 4 words in a row from. |
| `bot/chat.py` | `_cite` takes the newest user message, applies `add_missing_pointers`, and, if the model named no passage and stated no price, cites the passage the reply quotes (`quoted_passage`). The prompt has two small edits: "sports, TV" was added to the out-of-scope examples, and the medical rule now says "...Recommend speaking to a doctor, **but still give any relevant facts from the passages**." That second edit is for questions like "I use a walker, can I still do it?", where the answer is partly medical and partly on the page. |

Prompt growth is about 64 characters, roughly **16 tokens**. The prompt measured with the stub is about 2,110–2,180 tokens (characters / 4), plus history and completion. The text the guards append is added after the model replies, so it costs no tokens.

No changes to ingestion, `data/`, `bot/web.py`, `bot/llm.py` or `bot/safety.py`. I did not re-run `scripts/ingest.py`.

## (b) Turn by turn

All six passed. This shows that the code guards work and which wording the checks accept. **It is not evidence that the real model will write such replies.**

## (d) Risks and checks

- The answers depend on what the model writes for the walker and recall turns (see above). These two turns are the most likely to fail.
- The doctor-line guard matches health words in the user's message, so a non-medical "is it safe to travel to Tijuana?" also gets the doctor line. That is harmless, but it adds a sentence.
- Spelling correction could, in rare cases, turn an unknown word into a different indexed word that looks similar. The 0.85 cutoff and the 5-letter minimum keep this rare. Words that are in the index are never changed.
- The 4-word-quote citation can attach a source to a reply that merely reuses common page wording (for example "alternative cancer treatment in"). No check penalises an extra citation.
- Latency still depends on Groq. The Gemini fallback has taken 3–19 s before (see `notes/E02.md`).

Checks I believe are wrong: none.
