## (a) What changed, file by file

| File | Change |
|---|---|
| `bot/price_rows.py` (new) | If a user message names the label of a priced table row (for example "breast" in "| Breast Cancer | ... | $18995 |"), the passage holding that row is added near the top of the retrieved passages and the lowest-ranked passages are dropped to stay within `CONTEXT_CHARS`. Generic label words (cancer, treatment, therapy, package, program) don't count; all remaining label words must appear in the message. User messages are checked newest first, at most one passage is pinned. If the user is on another page (the focus page is ranked first), the pinned passage goes second so that page keeps the top place. Why: "What does breast cancer treatment cost?" ranked the price-list table 9th; the three near-identical package "Cost of ..." passages filled the budget and the table missed it by 47 characters. The bot then only had the general "costs start at $18,995" passage. |
| `bot/fallback.py` (new) | `add_quote_pointer()`: if a reply says the pages don't have something ("don't mention/list/say...", "not listed", "no information") and has no quote/contact pointer, append "You can request a free quote from PlacidWay to ask about this." before the Source line. Rule 4 of the product (don't know -> suggest a free quote) is now guaranteed in code instead of depending on the model. |
| `bot/chat.py` | (1) Calls `pin_price_rows()` after search and `add_quote_pointer()` on the final text. (2) `_earlier_questions()`: user messages trimmed from the history (max 3, 160 chars each) are added to the system prompt under "THE USER ASKED EARLIER". In this script the first question ("breast cancer") is dropped from the 8-message history by turn 5, so for "the listed price for her cancer" the model would otherwise only have the subject through the recalled price sentences. (3) Prompt: the out-of-scope rule now reads "Questions or requests unrelated to these pages (for example crime, weather, news, or writing prayers, poems or letters)". |

No changes to retrieval scoring, ingestion, `data/`, `tests/`, `personas/` or `botsuite/`.

**Prompt growth:** the rule edit adds about 60 characters (about 15 tokens) to every reply. The "asked earlier" block appears only once messages are trimmed: about 70-350 characters (about 20-90 tokens). The pinned passage replaces lower-ranked passages, so passage size stays within the same 4,800-character budget. Estimated prompt+history in the stub run: about 2,000-2,400 tokens (characters/4), the worst at turn 6; plus a completion of about 100-200 tokens.

## (d) Risks and checks

- Untested live: model wording on the prayer and instalment turns is the main uncertainty.
- `pin_price_rows` changes passage order for any question naming a price-list condition (breast, prostate, lung, pancreatic, colon, colorectal) or a comparison-table row. A lung cancer cost question now gets the price-list row first, so the bot may cite the price list rather than the profile (E01). Both pages state $18,995; if E01's check accepts only the profile it could change. When a package page is the focus (e.g. adenocarcinoma), that page keeps the top place.
- `add_quote_pointer` adds about 15 words to any reply that says the pages don't cover something. A persona with a tight `max_chars` limit on such a turn would see a slightly longer reply.
- Pre-existing, not changed: `_earlier_prices` can include an empty bullet when a trimmed reply ended with a blank line.

Checks I believe are wrong: none.
