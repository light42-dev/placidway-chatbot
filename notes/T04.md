# Notes: T04 Ahmed Al-Mansouri

The bot came from T01, E01 and E02 (see `notes/T01.md`, `notes/E01.md`, `notes/E02.md`). T04 improves it and does not add a second bot.

**Nothing in this work was tested against a live model.** The LLM quota was exhausted, so no Groq or Gemini call was made, the bot was not started, and `pytest -k T04` was not run. Every judgement below comes from reading the checks, running retrieval offline, and running `bot.chat.answer` with a stubbed model that returns replies I wrote by hand. Those hand-written replies show what a passing reply looks like; they are not evidence that the model will write one.

## What changed

| File | Change |
|---|---|
| `bot/arabic.py` (new) | `with_glosses(text)`: if a user message contains Arabic, appends English search words for the Arabic terms it recognises (cost/price, inpatient/outpatient, cancer types, ozone, countries, visa, booking, "back to", "first", ...). The table is general (about 45 patterns by subject), not tied to the scripted messages. Letters are folded (أ/إ/آ → ا, ى → ي, diacritics removed) and patterns match inside words, so prefixes such as ال, ب, ل, و need no handling. Only retrieval and focus detection see the glosses; the model still gets the user's own words. Before this, the index (English) matched nothing in an Arabic question unless it contained an English word. |
| `bot/recall.py` (new) | `focus_page(user_messages, last_cited)`: same as `find_focus_page`, except that a message that goes back to an earlier subject ("back to ...", "the first/original/earlier/previous one / treatment / question I asked") sets the focus to that subject: "first/original" means the first page the user raised, otherwise the one before the current one. Without it, "back to the first treatment" kept the focus on the comparison page (the newest page named), and the inpatient price would have come from the wrong page or not been cited as 7903. For messages without a back-reference it returns exactly what `find_focus_page` returned before. |
| `bot/chat.py` | (1) User messages pass through `with_glosses` before focus detection and search; focus comes from `recall.focus_page`. (2) New `MONEY` regex (`$`, `USD`, `دولار`, or a number like `30,000`) replaces the bare `"$" in ...` tests in `_earlier_prices` and in the citation fallback of `_cite`: Arabic replies often write "30,000 دولار" with no `$`, so before this the price sentence of an Arabic reply was not recalled once trimmed, and an Arabic price reply without `USED` numbers got no citation. (3) Prompt: the booking rule now ends "say so and suggest contacting PlacidWay for a free quote" (the `fallback` check needs a quote/contact pointer); the language rule gives the Arabic wording the checks accept: «لا أعرف» (don't know), «لا أستطيع» (can't), «عرض سعر مجاني» (free quote). Free paraphrases such as «لا تذكر الصفحات» or «طلب عرض مجاني» would fail `unknown`/`decline`/`quote`. |

No changes to `bot/retriever.py`, `bot/pages.py`, `bot/web.py`, `bot/llm.py`, ingestion or `data/`.

**Prompt growth:** `RULES` grew from 3,327 to 3,466 characters (+139, about 45 tokens because the Arabic words tokenize worse than English). The "PRICES YOU GAVE EARLIER" block can now also hold Arabic price sentences (up to 4), only when older replies were trimmed.

## Risks

- **Tokens.** The worst stubbed turn sent about 9,500 characters (system prompt about 8,300 incl. passages, the rest Arabic history). Arabic tokenizes at roughly 2.5–3 characters per token, so I estimate 2,500–2,800 tokens per reply with completion. Under 3,000 but with little headroom; Arabic replies near the 110-word limit are the main risk.
- **Arabic wording.** The `unknown`, `decline` and `quote` checks accept only a few Arabic forms. The prompt names them, but the model may still paraphrase.
- **Gloss table** covers common medical-tourism words only. Unseen Arabic questions on other subjects (for example "acupuncture") still retrieve little; the model then falls back to the focus page or says it does not know.
- **Back-reference detection** is a regex; "first ... one/treatment/question" could fire on a message that is not a back-reference. It only changes the focus bonus, not the passages' eligibility.
- Latency depends on Groq being available (Gemini fallback has been 3–19 s, see `notes/E02.md`).

## Checks I believe are wrong

None, but note: the Arabic phrase lists in `botsuite/phrases.yaml` are narrow. «لا تذكر الصفحات» ("the pages don't mention"), «لا تتضمن» and «يمكنني فقط» are natural refusals that the `unknown`/`decline` checks would reject. I steered the bot's wording rather than touching the suite.
