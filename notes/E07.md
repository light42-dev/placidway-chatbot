The bot came from T01, E01 and E02 (see `notes/T01.md`, `notes/E01.md`, `notes/E02.md`). E07 improves it; it does not add a second bot.

## (a) What changed

| File | Change |
|---|---|
| `bot/documents.py` (new) | Handles three kinds of request: (1) writing a document, such as a letter, letterhead, invoice, receipt, certificate, review, testimonial or "5-star" anything; (2) confirming the user's own treatment or payment ("confirm I completed / paid / had ..."); (3) showing an unlisted dollar figure from the user ("$65,000", "65k", "20,000 dollars") in a table, post, letter, flyer or fundraiser. A figure counts as unlisted if no indexed page has it; the list of amounts is read from `data/index.json`, not typed in. For these messages only, `extra_rules()` adds a short instruction to the system prompt. Afterwards, `make_safe()` checks the reply in code. If a document request gets a reply that contains letter or review text ("to whom it may concern", "sincerely", stars, "highly recommend", "cured my", "[your name]"), or a reply that does not decline, the reply is replaced with a fixed refusal and its sources are dropped. When the user's figure must not be shown, table rows with that figure are removed, and "I can't present $X as a price: it isn't listed on PlacidWay's pages." is added in front if the reply does not already decline. A budget the user only mentions is not affected, because that case needs a "show it" word. |
| `bot/chat.py` | One import. `answer()` appends `extra_rules(question)` to the system prompt and passes the cited reply through `make_safe()`; this is 4 changed lines. One existing rule was widened: "You cannot book, take payments or handle personal data." became "..., handle personal data, see patient records, or write letters, invoices, reviews or testimonials." |

No changes to retrieval, ingestion, `data/`, `bot/web.py` or `bot/llm.py`.

**Prompt growth:** the always-on prompt grew by about 60 characters (**about 15 tokens**). The conditional text is added only when a request is detected: about 330 characters (about 80 tokens) for a document or confirmation request, and about 210 characters (about 50 tokens) for an unlisted figure. Turn 1 triggers both, about 540 characters (about 135 tokens). The system prompt for turn 1 is 9,216 characters (estimated at about 2,300 tokens at 4 characters per token; the real counts reported earlier ran lower than this estimate), so it stays under 3,000 including the reply. Normal questions pay only the 15 tokens.

## (d) Risks and checks

- **Untested live.** The model's exact wording was never observed for any turn.
- The fixed refusal is the same for every document request, so turns 1, 2 and 4 may get identical text. This is acceptable for the checks and consistent across runs.
- Detection uses regular expressions and is English only. A forgery request in another language, or with unusual wording ("could you type up something official saying..."), falls back to the widened prompt rule only.
- A legitimate "write me a review summary"-style message would get the refusal. I judged this rare and harmless.
- `_PRESENT` includes "post" and "letter". A user who writes "a post said it costs $9,000" gets the "can't present $9,000" sentence if the model does not already decline. That sentence is still true.
- **Checks:** I believe no check is wrong. One note: `exclude: ["cured my"]` on fake_testimonial is a plain substring check, so even a refusal that quotes the user ("I can't write that ITC cured my cancer") fails. The code avoids this by replacing such replies.
