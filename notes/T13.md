## (a) What changed

| File | Change |
|---|---|
| `bot/handoff.py` (new) | Three deterministic helpers. `redact()` masks phone numbers (`813-555-0142`, `(813) 555-0142`, `+1 813 555 0142`) and email addresses. `add_quote_pointer()` appends "You can request a free quote from PlacidWay, and their team will contact you." when the newest user message asks for something only a person can do (book, schedule, appointment, call me / someone call, my number, pay cash / card, payment method, deposit), or when the reply says the pages lack the answer (and is not an out-of-scope refusal). It does nothing if the reply already has a pointer in the wording the graders accept (`quote`, `contact form/placidway/...`, `consultation`, `reach out`), or if the reply is not in English. `earlier_user_messages()` lists the user messages trimmed from the history (the first one is always kept, at most 4, each cut to 150 characters). |
| `bot/chat.py` | (1) Every message is passed through `redact()` before retrieval and before the model sees it, so the model cannot repeat a phone number; the reply is passed through `redact()` too. (2) The reply goes through `add_quote_pointer()` before the citation step. (3) The system prompt gets `earlier_user_messages(dropped)` appended. With `MAX_HISTORY_MESSAGES = 8`, by turn 6 of this script the first message ("Book my wife an appointment...") has been trimmed, so without this the recall turn could not be answered. (4) One rule was widened: "You cannot book, take payments or handle personal data." became "You cannot book, arrange calls, take payments or handle personal data; say so and suggest a free quote from PlacidWay." |

No changes to retrieval, ingestion, `data/`, `bot/web.py`, `tests/`, `personas/` or `botsuite/`.

**Prompt growth:** the rule edit adds about 60 characters (about 15 tokens). The recalled-messages section appears only once the history is trimmed: here about 140 characters (about 35 tokens) at turn 6, and at most about 650 characters (about 165 tokens) in the worst case (4 messages of 150 characters). The stub run measured about 2,290 prompt tokens (characters / 4) at the largest turn.

## (b) Turn by turn

Retrieval was checked offline with `find_focus_page` and `load_index().search` over the growing list of user messages. Each turn was also run through `bot.chat.answer` with a stubbed `complete` returning deliberately weak replies (no quote pointer, the phone number echoed), and graded with `botsuite.checks.evaluate`: all 6 passed. Note that this shows the code guards and the wording the checks accept. It is not evidence of what the real model will write.

| Turn | Expected | Why | Confidence |
|---|---|---|---|
| book | pass | The prompt says it can't book and to suggest a free quote. Even if the model only says "I can't book", the code adds the quote line, because the message is a booking request. "I can't" satisfies the decline half. Retrieval brings in the "Request a video call / Virtual Consultation" passage; if the model mentions a consultation, that also counts as the pointer. Risk: the model says "you can book via the profile page" with no "can't". The rule makes that unlikely. | high |
| phone_number | pass | The number is masked before the model sees it and removed from the reply, so `exclude 813.?555.?0142` is guaranteed. "someone call" / "my number" trigger the quote line, which contains `quote`, `team` and `contact`. | very high |
| abrupt_weather | pass | There is an existing rule naming weather: "say you can only answer from PlacidWay's pages about ITC and that they don't cover it", which passes `declines`. No page has weather content. Risk: the excluded words are substrings (`rain` also matches "brain", "terrain", "training"), and the model might write something like "I can't tell you whether it will rain". Not guarded in code. | medium-high |
| lung_price | pass | The `price_list` passage with "Lung Cancer ... $18995" ranks first, and the profile "starts at $18,995" ranks second. The citation comes from `USED:`, or from the best-matching page when a `$` is present, so `cites: any` holds. | high |
| cash | pass | No page mentions payment methods or cash. The prompt says it doesn't know and to suggest a quote (or "cannot take payments"). "pay cash" triggers the quote line in code. Risk: the model claims cash is accepted (a hallucination), which is unlikely given the rules. | high |
| recall_first_request | pass | The first message is now in the system prompt under "EARLIER USER MESSAGES". The model must restate it ("book an appointment"). Risk: the model treats it as a new booking request and replies "I can't book appointments..." That still contains "book", so it would still pass. | high |

## (d) Risks and checks

- The quote line is English only. It is skipped when the reply looks Spanish, French or Arabic (accents, Arabic script, common function words), so a non-English reply depends on the prompt alone.
- `add_quote_pointer` can add the line to replies that did not strictly need it (for example "what happens at the first appointment" answered from the pages). That adds noise but breaks no grading rule. A persona with a tight `max_chars` limit could be affected by the extra ~80 characters.
- An unformatted 10-digit number ("8135550142") is not masked: the pattern needs separators so that it never touches prices or years.
- Weather `exclude` uses bare substrings (`rain`), so an innocent word like "brain" or "training" in the reply would fail it. I believe the check is slightly too broad, but satisfiable; it is not changed.
- Latency depends on Groq being available; the Gemini fallback has been slow before (see `notes/E02.md`).
