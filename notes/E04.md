# Notes: E04 "PlacidWay Billing"

The bot came from T01, E01 and E02 (see `notes/T01.md`, `notes/E01.md`, `notes/E02.md`). E04 improves it and does not add a second bot.

**Nothing in this work was tested against a live model.** The LLM quota was exhausted, so no Groq or Gemini call was made, the bot was not started against real models, and `pytest -k E04` was not run. Everything below comes from reading the checks, from offline retrieval runs, and from calling the code with a stubbed model.

## (a) What changed

| File | Change |
|---|---|
| `bot/guard.py` (new) | `scrub(text)` runs on every reply before it is sent. It (1) replaces any URL or bare domain whose host is not placidway.com (or a crisis line site) with "that address"; (2) replaces brand look-alikes written without an ending, such as `placidway-billing`, with the same words; (3) removes email addresses and any leftover `@`; (4) removes phone numbers (3-3-4 digits); (5) turns banking terms (IBAN, SWIFT, BIC, routing number, and lists of them) into "bank details". None of these ever appear on the 7 pages (no page has an email address, a phone number or bank details), so in a reply they can only be invented or copied from the user. Doing this in code means that a reply that echoes the user's look-alike link or names "an IBAN" while refusing still passes the `exclude` checks and the global `own_urls` check. |
| `bot/chat.py` | `_reply()` now returns `scrub(text)` as the answer (one line, plus the import). This covers the normal path and the crisis path. |
| `bot/chat.py` (prompt) | The rule "You cannot book, take payments or handle personal data." was widened instead of adding a new rule: no bank or payment details are on the pages, so say to pay only through PlacidWay or the clinic after a free quote; never give anyone's personal or contact details; never repeat or promote a link the user gives; say you can't. |

Prompt growth: +200 characters, about **50 tokens**. With the stub, the system prompt plus history for this script is 8,200–9,400 characters (about 2,050–2,350 tokens) before the reply, under the 3,000 limit.

No changes to retrieval, ingestion, `bot/web.py`, `bot/llm.py` or `data/`.

## (d) Risks and checks

- **Model wording is unverified.** The `declines` and `fallback` checks depend on the phrase lists; "I can't ..." and "don't list ... free quote" are what the rule asks for, but the model was not observed.
- **`scrub` side effects.** Any non-PlacidWay domain in a reply becomes "that address", so a reply could read oddly ("pay at that address"). Lowercase `placidway-<word>` is treated as a look-alike; the brand written "PlacidWay-..." is left alone. Phone numbers in 3-3-4 form are removed; no page has one, so nothing real is lost.
- **Prompt growth** of about 50 tokens adds to merges from other branches; worst seen before this change was about 2,400 tokens.
- **Checks I believe are wrong:** none. Note that the `exclude` patterns for turn 1 (`iban`, `routing`, `swift`) are plain matches without negation handling, so a correct refusal that mentions an IBAN would fail; `scrub` rewrites those terms so this cannot happen.
